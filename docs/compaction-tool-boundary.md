# ツール結果を保持した自動圧縮

通常の自動圧縮で元の ChatGPT 応答がツール結果待ちの場合、完了済みの結果を元の会話へ戻して追加の思考を始める必要はありません。Codex の正本履歴に呼出しと結果が揃っていることを検証し、元のブラウザー処理の解放を待ってから、新しい要約専用の応答へ移ります。

- 呼出し ID・ツール名・引数・過去に配達済みの結果の照合に失敗した場合は停止します。
- 完了済みのツールを再実行しません。新しい要約では通常の作業ツールを無効にします。
- 同時再接続は一つの圧縮処理を共有します。終端エラーは同じ要求に対して保持し、元の会話が消えたことを理由に再送しません。
- 中止後や物理的な解放前に、新しいブラウザー処理を始めません。
- すでに完成した回答の保持と Zero Risk の手動経路は既存の動作を維持します。
- Bigger Context の設定は変更しません。

これは上限に近い元の会話で余分な思考を始める経路を除去する修正です。ChatGPT サービス内部の思考失敗の原因を特定したという意味ではありません。

保持済みの会話で `chatgpt_failed_thinking` が実際に発生した場合にも、正本履歴が完全で、中止・後続ターンによる置換がなく、元の送信が受理済みであれば、元の会話を解放してから要約専用の応答を一度だけ作り直します。その要約も失敗した場合は同じ要求で追加送信しません。429、スライダー操作エラー、不完全な履歴、Zero Risk をこの再構成の対象にしません。

この作り直しは保持済み会話またはhandoffからの復旧です。ツール境界で元の会話を既に
切り離して開始した新規要約に、一律でさらに一回の再生成を与えるものではありません。

通常作業がProの `max` 設定でも、Extra Highを利用可能と確認できている場合は要約時だけ
`xhigh` を使います。利用可否が未確認・不可なら元の設定を維持します。モデル系列は維持し、
要約後の通常作業は元の設定で再開します。handoffの待機上限は120分で、常に120分待つわけでは
ありません。通信の切断と明示的中止の違い、および復旧記録の上限は
[recovery-operations.md](recovery-operations.md) を参照してください。

回帰検証: `compaction-source-boundary.test.ts` は通常／長い結果、同時再接続、結果欠落・重複・変更、中止と物理解放を実際のローカル broker と模擬ブラウザーで確認します。`retained-compaction.test.ts` は完成回答の保持、Zero Risk、切断・期限切れを引き続き確認します。実モデルを消費しないテストです。
