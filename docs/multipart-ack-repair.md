# 分割送信の2通目へ進まない問題

調査・反映日: 2026-09-27。修正版: `6.1.1-fork.6`。

## 原因と修正

1通目が送信済みと確認された後、ChatGPTの受領確認が表示されていても、
送信したuser要素がDOMからなくなるとassistantを結び付けられず、
次の分割を送らないまま待機時間を使い切っていた。
診断記録にはuser要素0件、assistant要素1件と生成終了後の操作ボタンがあり、
同じ状態をChromeのローカルDOMで再現すると修正前の処理は失敗した。
実サービス側でuser要素が消える内部理由までは確定していない。

分割送信の準備段階だけ、送信時に確認したuserのIDを保持し、今回の
ランダムなトランザクションID・分割番号・SHA-256を含む受領確認の
本文が完全一致した場合にassistantを結び付ける。
以前から存在するassistant、別のuserが現れた場合、複数の一致候補は採用しない。
通常回答の所有権判定、受領確認の内容検査と生成終了待ちは維持する。

## 検証と反映

新規11件、関連149件の合計160テストが成功した。
2分割・6分割で、各受領確認から次の送信処理へ一度だけ進むこと、
異なるID・番号・ハッシュ、余分な本文、引用された受領確認、別user、
重複した受領確認を誤採用しないことを確認した。
型チェック、ランタイムビルド、6,019ファイルのmanifest照合も成功した。

ローカル反映は10:46 JST、再起動後の確認は10:47 JSTに完了した。
インストール先と実効ランタイムのハッシュ一致、`6.1.1-fork.6`の読み込み、
サービス正常、リクエスト受付有効、モデル一覧取得成功を確認した。
待機用の自動タスクは削除済み。

送信検証は実Chromeを用いたローカルDOMフィクスチャであり、モデル選択と
サービスへの送信はスタブ化している。修正版による実際のChatGPTへの
送信・応答完了までの受入試験を実施したという意味ではない。
配布・反映の詳細記録はGit管理外の`output/multipart-ack-repair-20260927/`に保存した。
