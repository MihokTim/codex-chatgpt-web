# 更新時のセッション検査による起動失敗の修正

対象：6.1.1-fork.3。調査日：2026-09-26。

20:08 JSTの6.1.0から6.1.1への更新では、アカウント機能検査がモデルメニュー内の
スライダーを70秒待って失敗した。設定は6.1.0に戻され、6.1.1のランチャーは
`needs-setup`となり、Codexのルートも切断された。別途行われた20:11のブラウザー
smokeは成功しており、ブラウザー単体の成功はランタイムの復旧を意味しない。

機能検査だけがEnterキーでメニューを開き、実際に開いたことを確認していなかった。
通常のモデル選択が利用する共通のactivationを機能検査にも適用する。所有controlの
状態確認、クリック、必要な場合の一度のprimary pointerdownを経てスライダーを検査する。
検査失敗を低いアカウント権限として保存する動作は導入しない。

更新処理・ブラウザー処理中はセッション更新の通知を表示しない。これにより検査と
ログアウトが競合する操作を抑える。認証情報の削除や再ログインは修正に含めない。

`tests/session-capability-activation.test.ts`はWindowsのheadless Chromeで、Enterが
無効なメニュー、一度のクリック後に実体が閉じているメニュー、閉じる途中のメニューを
再現する。機能検出の結果、メニューが開かれた証拠、終了後の閉鎖、下書き保持、送信ゼロを確認する。

配備・実動作の結果は`output/session-startup-repair-20260926/`に記録する。

## 非表示画面でのモデル切り替え停止

起動復旧後の実送信で、5.6のfamily選択にも停止があることを確認した。
Playwrightの`noDefaults: true`はブラウザー全体への変更を防ぐ一方で、通常設定される
focus emulationも無効にする。非表示のElectron WebContentsViewではrAFが停止し、
Playwrightの安定性待ちとChatGPTのメニュー状態遷移が完了しなかった。

ネイティブtarget IDで所有権を確認した自動操作用の画面だけにfocus emulationを適用する。
そのCDP sessionは接続中だけ保持し、ブラウザー接続を閉じる際に解放する。
クリックの安定性確認・モデル選択の読戻しは維持する。

`tests/launcher-hidden-frames.test.ts`は独立した非表示Electronを起動するWindows回帰テスト。
修正前は実機と同じクリック待機エラーとなり、修正後はrAF内の選択遷移まで成功した。
メインウィンドウは表示せず、接続対象が所有する一画面だけであることも確認する。
