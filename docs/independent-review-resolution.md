# 独立レビューへの対応 — 2026-09-23

対象は上流 `eaf4f09` からローカル `9aec271` までの36コミットと、その独立レビュー。
「Sol Pro共存障害を最優先で調査」の記録も照合した。実環境への入れ替え保留、Bigger Contextの
設定維持を引き継ぎ、今回のサブエージェントはnative Astraだけを使用した。

## 7件の指摘の再評価

| 指摘 | 判断と対応 | 主な回帰検証 |
| --- | --- | --- |
| F1: 古い回答の再表示を現在の回答として採用 | 妥当。新規ユーザーの識別子を送信観測時に保存し、そのユーザーに続く回答だけを採用。表示件数による代替判定を削除 | 古いACKの別ID再表示、ユーザー内側DOMの仮想化、正しい回答へのbinding |
| F2: ChromeのテストパスがWindows固定 | 妥当。既存のOS別 `defaultChromeExecutable()` を使用し、明示的な環境変数上書きは維持 | Windowsの合成DOMテスト。macOS/Linuxでの実行は別途必要 |
| F3: HTTP切断で共有復旧が永久に失敗 | 妥当。物理実行の終了処理とHTTP接続の生存を分離。切断しても共有の再開枠は維持 | 終了処理中の切断、その最中／完了後の再接続、接続なしでは生成しない、明示的中止 |
| F4: 配達normalizerがcwdなし更新を拒否 | 妥当。通常指示と配達で共通の環境解決policyを使用 | 正規配達＋日付更新＋追加指示、空のGitメタデータ、本文・宛先・所有者・権限改変の拒否 |
| F5: 生のモデル操作例外で再送される | 妥当。モデル設定と送信直前確認の境界で未分類のUI例外を専用終端エラーへ変換 | 実DOMのTimeoutError、型付きエラーとAbortErrorの保持、同じHTTP要求でworkerを再起動しない |
| F6: dirtyからdirtyへのビルド中変更を見逃す | 妥当。Git commit/treeと別にビルド入力のパス・内容hashを記録し前後比較 | 同じサイズ・mtimeで内容だけ変更、追加・削除・改名、Gitなし、対象外ファイル、HEAD変更 |
| F7: 最大2回の再接続が3回になる | 妥当。viewport内部で消費した試行数をDOM観測側へ返す | `[1,2,2]` を `[1,2]` に制限、成功したDOM観測後だけ予算をリセット |

## その他の改善点

- **設定画面の重複操作:** 選択後の確認を一回に集約。各送信直前の検証と、スライダー範囲・系列・値の確認を維持する。
- **テストの分離:** `local-customizations.test.ts` を廃止し、モデル経路・ブラウザー系列・HTTP本文・DOM応答の各テストへ移す。日本語の思考停止／失敗はソース文字列の切出しではなく、本番DOM snapshot経由で確認する。
- **履歴ガードの失敗時処理:** staging・置換・復元を独立したモジュールへ集約。receiptを最後に置換し、通常のI/O例外で元のバイト列へ戻す。初回導入、更新、receipt保存、構文検査、復元の失敗、残留stagingからの再試行を一時ディレクトリで検証する。
- **ビルド識別情報:** 変化する日付・上流SHAを検証スクリプトに重複して書かず、`fork-metadata.json` を正本にする。製品識別・完全SHA・schema・日付の検証は維持する。
- **HTTPサイズ検証:** ヘッダーの宣言だけでなく、圧縮前後の実際のバイト列を境界値で検証する。受入サイズの上限であり、展開中の最大メモリを保証するものではない。
- **Solツール試験の診断:** 失敗理由を機械可読にし、モデルの自己申告とネイティブイベントによる証拠を区別する。実モデルを使う試験自体は実行していない。
- **障害記録プロセスの起動確認:** WMIの作成戻り値だけで成功を宣言せず、PID・実開始時刻・running・最初のsampleを期限内に照合してからreceiptを書く。実レジストリを変更しない模擬installerと一時プロセスで検証する。
- **復旧記録512件の運用:** `/healthz` に使用数・上限・残数を公開し、保存・終了・再起動後の新しい指示からの再開を文書化する。TTLで記録を捨てて再試行枠を復活させる変更は行わない。
- **説明の訂正:** Latestは固定Astraの識別保証ではないこと、圧縮だけのmax→xhigh、DEV Mediumの適用条件、通信維持probeとmultipart試験の違い、特定MCPサーバーへのパッチ、保持済み会話の要約復旧範囲を明記する。古い5分コメントとfeature inventoryも更新する。

## 採用しなかった変更と理由

| 改善案 | 判断 |
| --- | --- |
| 元の36コミットを再び分割・統合して書き換える | 目的の混在という指摘自体は妥当。ただし既存の検証・導入記録がコミットIDを参照している。今回の修正を原因・責務別に追加し、元の履歴と対照できる形を保つ。公開mainの強制更新はしない |
| 大きなbrowser worker・adapterの全面分割 | 今回の不具合に関係する共通判断を抽出・集約した。全面移動は状態遷移の確認を難しくするため行わない。ファイル行数だけを理由に再構成しない |
| 要求設定とaccount capabilityのIPC構造を全面変更 | 要求・能力・観測を別概念とする指摘は妥当。既存helperとのcapability交渉・ワイヤ形式を変更する必然性は今回確認しておらず、プロトコル移行は別設計とする。系列を含む実行・圧縮・会話キーは維持する |
| 通常復旧と圧縮復旧を一つの状態機械へ統合 | 両者はツール実行の可否・正本の必要条件・保持会話の扱いが異なる。共有終了処理とHTTP観測の関係を修正し、二つの復旧方針は別に維持する |
| 配達検証のキャッシュ・索引 | 合成128MiB履歴で同期照合の中央値347.61ms、timer遅延348.25msを確認した。性能上の懸念は残る。今回、本番要求頻度での障害や許容遅延違反は未確認。切詰め・差替え・中止の失効規則なしに正本検証を省略しない |
| dirtyビルドを一律禁止・全ビルドを別checkout化 | 開発用dirtyビルドは継続し、内容hashで検出する。配布用には既存のclean必須設定を使う。前後比較のため、一時的に変更して元へ戻す操作まで保証するものではない |
| history guardの対象版を広げる | 特定版の正確なserverバイト列に対するパッチであり、version/hashの制約を維持する。未知の版やスキーマには適用しない |
| 古いstagingをまとめて削除する | 別実行が所有する可能性がある。一意なstaging名で再試行可能にし、自分のstagingだけを清掃する |
| Windowsのsymlink権限を変更して既存テストを通す | 環境制約であり製品コードの不具合ではない。OS権限は変更せず、未通過として報告する |
| 実ChatGPTでSol/Astraの5並列を受入確認する | 実環境の入れ替え保留を引き継いでいる。模擬DOM・ローカルbrokerによる回帰と、候補ビルドの検証を実施し、実モデルの共存確認は導入後の残件として明示する |

この対応で、Sol/Astraの実サービス側の容量・思考失敗や、Codexアプリ強制終了の根本原因まで
確定したとは扱わない。今回修正するのはソースで確認・再現できた境界条件と、診断・検証上の不足である。
