# 頻度制限とモデル操作の復旧（6.1.0-fork.3）

## 原因と修正

モデルのeffort操作では、フォーカスが維持できずfalseを返す場合だけメニューを開き直していた。DOMの置換・消失によってLocatorがTimeoutErrorを投げると、その経路を通らず `stage=effort-focus` で終了していた。消失する実DOM fixtureで修正前の失敗を再現し、復旧対象を限定した例外処理を追加した。操作全体で5秒のフォーカス予算を共有し、同じURL・documentのメニューを一度だけ開き直す。中止、認証・所有権・選択範囲の異常、別モデルへの変更は復旧対象にしない。元のfamily・effortの検証を維持する。

頻度制限ダイアログは、生成POSTのHTTP 429とは独立して画面に表示される。既存コードはダイアログだけでACK待ちを終了させていた。fork.3は以下の条件がすべてそろった場合に限り、同じ応答の監視を継続する。

- 同じ所有page・同じSendで、生成POSTの2xxとDOM等による送信受理がそれぞれ確認できている。
- 直近5秒に、そのSend中に開始したconversation GETの429を観測している。生成・認証・その他の拒否が混在していない。
- ダイアログを閉じた後の新しいDOM観測で、新しいユーザー発言に対応する生成中状態または応答を確認できる。完了したmultipart応答では期待するACKが一致する必要がある。
- 帰属不明ダイアログとしてのcooldownを共有schedulerへ正常に報告できた。
- そのSendでこの復旧をまだ実施していない。

GET 429とダイアログの時間的な近さだけでは原因を断定しない。2xxだけでも意味的成功とは見なさない。帰属不明・古い証拠・別page・受理不明・実際の生成429・認証障害・復旧後の再表示では停止する。確認済みの応答を監視し続ける処理であり、生成の再送、ページreload、ツール再実行、ACKカーソルの巻き戻しは行わない。既存の完了検証・応答異常検出・待機期限は維持する。

新しいSendは、generationだけでなくconversationの既知cooldownも尊重する。次の送信に伴う補助的な会話取得が制限中の通信を増幅しないよう、親タスク・子タスク・圧縮で待機を共有する。受理済みの生成監視はこの待機の対象外である。帰属不明ダイアログを他タスクへの一律の制限へ拡大することはない。

リクエスト監視で完了済みの報告Promiseを保持し続けていた配列を、未完了だけを保持するSetへ変更した。終了時には残る報告を待ち、page listenerを解除する。Electron側のHTTP記録は診断ログであり、共有schedulerへの二重報告ではない。今回参照したbridgeソースにはconversation GETの反復取得処理はなく、ChatGPT側の取得間隔自体は変更していない。

## 検証

`effort-focus.test.ts` は実DOMの置換・消失、フォーカス競合、日本語の両Pro family、範囲異常、中止を扱う。`request-limits.test.ts` は現在Sendへの帰属、古い429、別frame、2xxだけの状態、認証障害、報告失敗、再接続、中止、遅延して届く生成拒否を検証する。

`auxiliary-rate-limit-recovery.test.ts` は6partの第3ACK待ちで補助GETの429とダイアログを挿入し、正常継続時にはSendとACKが各一度だけ進むことを確認する。受理を再確認できない場合・帰属不明・生成POST拒否は第3partで停止し、ACK1/2を保持する。元の `multipart-rate-limit-recovery.test.ts` の送信前復旧と送信活性化後の非再送も維持する。launcher側ではconversation cooldownの共有・Retry-After・重複報告・解除後のSendを検証する。

fork.2の対象タブ限定CDP接続、初期接続の中止・切断完了待ち、同じpageの再接続、圧縮と通常タスクの有界な復旧も含む。実サービス側の混雑・429・認証障害が起きないことを保証する修正ではない。

## 配備の確認

buildIdとソースcommit、両runtimeのmanifestとSHA-256、新しいlauncher/daemon PID、healthを照合するまで配備完了とは扱わない。以前のfork.2配備記録はアイドル待機の期限切れでFAILEDとなっているため、ソース修正済みと稼働版反映済みを区別する。検証・配備証跡は `output/request-control-recovery-20260925/` に保存し、以前の失敗結果は上書きしない。
