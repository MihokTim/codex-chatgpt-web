# ブラウザー接続と圧縮後の復旧（6.1.0-fork.2）

2026-09-25に、圧縮用multipartの第1区間が上流の「Something went wrong」で失敗し、そのまま復旧不能になる事象と、browser_pageの接続が60秒でタイムアウトする事象を確認した。後者は次の接続にも約59秒かかっていた。healthの成功だけでは、これらのブラウザー実行経路の成功を確認できない。

## 接続の変更

Playwrightのブラウザー全体への接続は、対象ページを選ぶ前に他のページの初期化も待つ。公開されたカスタムCDP transportを使い、ルートの自動接続要求をdescriptorに登録された単一のtargetへの接続へ置き換える。子フレームへの接続は維持する。秘密情報、回答本文やツール引数を接続ログへ保存しない。

CDPのメタデータは同じloopbackホスト・ポートのブラウザーendpointに限定する。呼出側の中止と接続全体の期限を初期handshakeから適用し、失敗したsocketを閉じてから処理を終了する。切断でユーザー所有のページを閉じない。Playwrightの既定のfocus・media上書きも無効にし、対象外タブへの影響を抑える。

## 復旧の変更

送信前であることが確認できる一時的な準備エラーは、同じリクエスト内で復旧する。旧処理の終了と再試行待ちの間も同じsessionを保持し、同時再接続が再試行回数を重複消費したり、別の送信を始めたりしないようにする。

要約専用の新規圧縮は、同じ共有ownerの中で合計最大3回まで試行する。各失敗後に旧ブラウザー処理の終了を確認し、待機してから次へ進む。圧縮にはローカルツール権限を渡さず、元のモデルと推論設定を維持する。通常タスクを再実行するための復旧ではない。使用量制限、認証、停止、中止、未知のエラーはこの再試行対象にしない。

通常タスクでは、既存のfailed-thinking復旧に加えて、応答に結び付いた一時的なserver-errorも、完了したツールの呼出・結果を正本履歴で照合できる場合に一度だけ継続する。実行中ツール、履歴欠落・変更、途中の最終回答、中止、後続指示への所有権移動がある場合は再送しない。復旧できない送信済みserver-errorを無条件のnative再試行へ渡すことも防ぐ。

## 検証

`tests/transient-compaction-recovery.test.ts`で圧縮の一時障害、最大回数、共有owner、使用量制限と中止を検証する。`tests/failed-thinking-recovery-integration.test.ts`と`tests/chatgpt-web-harness.test.ts`で、完了済みツールを保持した継続と同時再接続を検証する。

`scripts/smoke-owned-cdp.ts`は新しい一時Chromeプロファイルだけを使用する。別のタブで5秒間の同期JavaScriptを実行し、旧方式の接続タイムアウトと、対象タブ限定方式の接続・入力・クリックの成功を比較する。日本語・空白のあるパスからの添付、切断後のページ維持、応答しないloopback CDP接続の中止と再接続も確認する。個人の認証済みブラウザーには接続しない。この成功を実アカウントでのPro生成成功と同一視しない。

正式な全体検証は`bun run verify`。配備はアクティブなHTTP・ブラウザー処理がともに0であることを確認してから行い、稼働中のタスクを強制終了しない。
