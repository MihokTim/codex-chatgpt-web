# 復旧記録の容量と運用

通常作業の思考失敗は、Codexの正本に完了済みツール結果がそろい、明示的中止や
所有者変更がない場合に一度だけ再開する。古い実行の終了処理はタスクに属する。
HTTP接続がその途中で切れても終了処理は完了させ、次の接続が同じ再開枠を利用できる。
接続がない状態では置換生成を開始しない。明示的中止は引き続き再開を禁止する。

同じ古い要求に再試行権を与えないため、以下の記録はブリッジプロセスが終了するまで保持する。

| `/healthz` の項目 | 記録するもの | 満杯時の動作 |
| --- | --- | --- |
| `recovery_fences` | 一度だけの通常復旧を予約した実行 | 新しい自動復旧を予約せず、元の失敗を返す |
| `compaction_failure_fences` | 確定した圧縮失敗 | 新しい圧縮を `compaction_failure_tracking_full` で拒否する |

各項目は `used`、`limit`（512）、`remaining` を返す。タスクID、プロンプト、結果本文は
返さない。使用量は成功した全タスク数ではない。上限に達しても既存の記録は削除せず、
同じ要求に対する失敗や一度だけの復旧という制約を維持する。

残量が少なくなったら、作業結果と未完了タスクを保存し、実行中のタスクを正常に終了させる。
再起動が許可されたタイミングで `active_http_turns` と `active_browser_turns` が0であることを
確認し、ブリッジを通常の手順で再起動する。再起動はメモリ上の記録を失うため、失敗した古い
HTTP要求をそのまま再送せず、保存済み結果を含む新しいユーザー指示から再開する。
稼働中のタスクを停止したり、自動的に記録を削除したりする運用は行わない。

圧縮の復旧は別の条件を持つ。保持中の元の会話・handoffが思考失敗した場合には検証済み履歴から
要約を一度作り直せる。一方、ツール境界で元の会話を切り離して開始した新規要約の失敗まで、
常にもう一度生成する設計ではない。詳細は [compaction-tool-boundary.md](compaction-tool-boundary.md) を参照。
