# 送信待機・応答観測・取消境界の修正

対象候補: `6.1.2-fork.10`。インストール済み環境への反映結果は、Git管理外の
`output/repair-20260928/`に別途保存する。ソース修正、テスト成功、配備成功は区別する。

## 分割受領確認で次へ進まない問題

従来の修正は、一度確認したuser要素が後で消える場合を扱っていた。今回の記録では、
送信受付を生成中の表示から確認した一方、user要素を一度も観測できていなかった。
正しい`CODEX_MULTIPART_ACK`が表示されても、user IDを待ち続けて期限切れになった。

物理送信の受付を確認した場合に限り、今回のランダムなトランザクションID・分割番号・
SHA-256と完全一致する受領確認を結び付ける。既存の回答、別のuser、複数候補は拒否する。
この例外は準備用の受領確認だけに適用し、通常回答の所有権判定には使わない。

実ChromeのローカルDOM試験では、userが一度も現れず生成中表示だけを検出する条件、
受付証拠がない場合の拒否、通常回答・別トランザクション・別user・重複候補の拒否を確認する。
既存の2分割・6分割の次段階への遷移試験も維持する。

## 応答観測とエラーの区別

保存された9月27〜28日の標準Codex履歴では、従来の
`ChatGPT stopped responding after the task started`という文言で終了した記録は16件あった。
これは保持された履歴の終了記録の集計で、画面上の再接続表示回数や全期間の総数ではない。
保持された2つのランチャーログでは、ページ再接続期限切れ12件、分割受領待ち期限切れ2件を
確認した。取消による終了はこれらの件数に含めない。同じ文言の全件を同じ根因とは扱わない。

所有タブ用CDP通信は、連続して受け取ったイベントを同じ実行タスク内で同期処理していた。
Playwrightの標準通信と同様に、イベント間でPromise継続が実行される順序を保つ。
同一タスクで複数イベントを配送するフィクスチャでは変更前の失敗と変更後の成功を確認した。
ただし実Bun WebSocketの単純な連送では旧実装でも正しい順序となった。これは標準通信の
契約に合わせる防御的な変更であり、過去の実サービス停止の根因修正とは扱わない。

再接続前と接続失敗時に、処理段階・未応答のCDPメソッド名・経過時間を残す。
ページ本文、引数、認証情報、URLを診断へ含めない。観測接続の失敗、準備用受領確認の期限切れ、
送信後の応答の特定失敗を区別する。観測不能だけからChatGPT自身の停止を断定しない。
いずれも送信済みの作業を自動再送しない。HTTP経路の回帰試験で再送拒否と、新しい指示の受付を確認する。

## 子の引継ぎと取消

前の親に属するnative子IDを、新しい親の`wait_agent`に渡した場合の`not_found`は、
子が最初から起動しなかったことを意味しない。調査した4子には実際の実行・終了記録があった。
OrcaのDispatch IDとnative Codexの子IDも別の識別子である。再起動による成果の重複生成を避け、
元の親と保存成果を照合して回収する。

自然な親ターン終了、HTTP観測の切断、明示的な取消は異なる。明示的な取消が先に届いた場合、
後から登録される同じnativeターンや圧縮処理にも取消を適用する。圧縮のtoken待ち・取引登録の
途中でも取消を確認し、取消後に新しいブラウザー処理を開始しない。

これらはWebブリッジが所有する処理の取消境界である。別のnative子プロセスすべてを
自然な親終了時に無条件停止する機能ではない。

## 履歴ブランチの扱い

旧5.xと初期V6の分岐には、現mainへ移植済みの変更と、意図的に廃止した仕様が混在している。
既存の[V6レビュー](v6-fork-review.md)と[追加修正記録](v6-review-resolutions.md)に従い、
旧ブランチ全体を再マージして廃止済み仕様を復活させない。削除前に全参照をGit bundleへ保存し、
Gitによる検証を行う。旧stashの差分は既存の起動待機修正コミットとpatch-idが一致した。
最終的な残存ブランチ・remote・配備bundleは統合作業後に別途照合する。

## 検証環境

Windowsの単一共有グローバル環境による一括試験では、複数ファイルのloopback通信が
期限切れになった。同じ試験はファイルを分離すると通過したため、標準の`test`コマンドを
Bunの`--isolate`で実行し、ファイル間のグローバル状態を分離する。失敗をskipしたり、
製品のタイムアウトを延長したりして合格に置き換えない。

ACK・取消・再接続の独立レビューでは、今回追加した容量到達時の試験を含む138件と
型検査を確認した。取消容量の受付判定は、既存ownerの終了処理より前に行う。
ランチャー試験は376件成功、5件が既存の環境条件によるskip。全体試験と配備後の
実接続確認の最終結果はローカルの検証記録に保存する。

追加の実ブラウザー試験で、複数ACK候補の片方のDOM読取が期限切れになると、
読めた1件だけを唯一のACKとして選ぶ問題を検出した。候補の未観測を「不一致」と
扱わず、全候補を確認できるまで所有権を確定しない。片方の観測失敗を固定的に再現する
回帰試験も追加した。送信後にユーザー要素が消える場合の改善と、重複拒否を両立させる。
