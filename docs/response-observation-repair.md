# 応答監視の停止と完了操作未描画への対処

対象: `6.1.1-fork.7`。今回の作業はローカル修正とインストール済みアプリへの反映。

## 確認できた事実

2026-09-27 の実行記録では、ツール要求を受け取ってから90秒後にMCP呼び出しが期限切れになったケースが2件、回答本文の表示後に完了操作を確認できず停止したケースが1件あった。スクリーンショットの共通エラーだけから、すべてを同じ原因と断定することはできない。

通常回答、長い入力、ツール2回を含む小さな実送信テストでは、変更前にも成功した。元のユーザー作業を再送しておらず、報告された3件すべての原因を確定・再現したという検証結果ではない。

## 修正した停止経路

- `isVisible` やページ側タイマーの応答が返らないと、ツールの実行前確認へ進めない読み取りがあった。ホスト側の監視期限を設け、既存の同じタブへの再接続を使う。初回の回答結び付けだけでなく、回答監視中にも適用する。
- 回答DOMの評価にもホスト側の期限を設ける。Playwrightの要素待機期限だけでは、評価開始後の無応答を止められない。
- 生成とツール実行が止まり、本文はあるのに完了操作が出ない状態が5秒続いたら、結び付け済み回答の末尾を一度だけ表示する。本文・完了操作の再観測と、既存のMCP完了フェンスが成立するまで成功にはしない。完了操作が出ないままなら従来の期限で失敗する。
- 長いツール引き渡し待ちの時間を診断に残す。本文・ツール引数・認証情報は記録しない。

再送、ページ再読み込み、別回答の採用、タイムアウトだけを理由にした成功判定は行わない。ツール承認や認証の扱いは変更していない。

## 回帰確認

応答しないアラート読み取り、応答しないDOM評価、ツール実行前の確認順序、完了部分の再表示回数、生成中・ツール実行中の抑止をテストする。実ChromeのローカルDOMで、画面外の完了操作が表示位置への移動後に描画される条件を確認する。通常回答の所有権、分割ACK、ツール結果の継続、キャンセル・再接続の既存テストも対象とする。

実行結果とデプロイ証拠は `output/completion-repair-20260927` に保存する。実サービスであらゆる停止が発生しないことを保証するものではない。
