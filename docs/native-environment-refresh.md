# 日付更新後の環境引継ぎ

Codexは長いターンが日付をまたぐと、現在の日付・タイムゾーン・ファイルシステム設定を含む環境更新を送ることがあります。この更新には作業ディレクトリ（cwd）が含まれません。

従来は、その後の追加指示に対して元の環境と更新後の環境が競合していると判断し、`missing cwd in trusted Codex environment context` で停止する場合がありました。Sol Proなどの子担当でも起こり、クライアントの再接続で同じ失敗が繰り返されます。

修正後は、同じターンの元の環境と指示の組を確認し、Codex由来と明示された日付更新だけを部分的な環境の申告として読みます。元の申告から補ったcwdを含め、すべての申告の作業ディレクトリ・許可ルート・権限を、そのターンの正本rolloutと照合します。正本がない場合や内容が異なる場合は受理しません。キャッシュだけでの復旧や権限の拡張は行いません。

回帰テストは、親・子タスク、複数回の日付更新、正本欠落・古いターン、出所のないXML、異なる許可ルート・権限を確認します。実モデルの生成や実環境の入れ替えは不要です。
