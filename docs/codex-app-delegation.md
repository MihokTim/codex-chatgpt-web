# Codex Appから受け取るタスク指示

Codex Appの `create_thread` と `send_message_to_thread` は、受信側に通常のユーザーメッセージではなく、`namespace: codex_app` の `function_call_output` を保存する。この項目にはネイティブIDとターン所有情報があり、受信側の対応するツール呼び出しと `call_id` は存在しない。

以前はこれを通常のツール結果として処理していた。そのため、新規タスクでは正しい作業フォルダーが記録されていても `missing cwd in trusted Codex environment context` になり、既存タスクでは古いユーザー指示と新しいターンIDを比較して `current user message conflicts with native Codex turn_id metadata` になっていた。

WebのHTTP要求処理は、受信先の正規rollout・現在のターン・権限・各受信項目を照合し、確認済みの配達項目だけをモデル入力内のユーザー指示へ正規化する。元の配達本文、送信元、ネイティブID、ターン所有情報は保持する。Codexの保存履歴は書き換えない。送信元の作業フォルダーや親子関係を受信先へ引き継ぐこともない。

照合できない配達はブラウザ起動前にHTTP 400で終了する。実際のツール呼び出しに対応する結果や、一般のメッセージに含まれる同じXML文字列は、この配達形式として特別扱いしない。

テストは新規・既存タスクの受信、同じ受信の再接続、新しい指示への更新、圧縮時の指示保持、思考失敗からの復旧に必要なツール履歴、受信先・本文・ターン・環境の不一致、中断済みターン、およびHTTP経路を確認する。rolloutは固定サイズのチャンクで逆向きに読み、履歴全体を一度にメモリへ取り込まない。

この修正の対象はタスク間の指示受信である。ChatGPT側の思考失敗、モデルスライダー操作、Codexアプリの強制終了を包括的に解消したことを意味しない。
